## 5. v2 schema 摘要

> 來源：<https://nhentai.net/api/v2/openapi.json>（`info.version` = `2.0.0+4a31779`，2026-11-06 讀取）、<https://nhentai.net/api/v2/changelog>。
> 實測（桌機 curl、原生 HTTP、帶描述性 UA）：v2 詳情、`/api/v2/cdn`、封面 CDN 都直接 200，**沒有 Cloudflare challenge**；舊 `/api/gallery/{id}` 一律 `403 text/plain`「Use new API https://nhentai.net/api/v2/docs」。

### 5.1 `GET /api/v2/galleries/{gallery_id}` → `GalleryDetailResponse`

- `gallery_id`：path，integer。`include`：選填，逗號分隔 `comments,related,favorite,suggestions`（本 App 不帶）。
- 回應：200 `GalleryDetailResponse`；404 / 429 為 `ErrorResponse` `{ "error": string }`（例：`{"error":"Gallery not found"}`）；422 `HTTPValidationError`。
- 速率限制：**匿名 20 次／分鐘／IP**（有金鑰 45）。429 回應帶 rate-limit 標頭，且 429 不計入額度（changelog）。

| 欄位 | 型別 | 必要 | 說明 |
| --- | --- | --- | --- |
| `id` | integer | ✓ | gallery ID |
| `media_id` | **string** | ✓ | 數字字串，例 `"1205270"` |
| `title` | `GalleryTitle` | ✓ | `english`(✓)、`pretty`(✓)、`japanese`(string\|null) |
| `cover` | `CoverInfo` | ✓ | `path`、`width`、`height`（皆必要） |
| `thumbnail` | `CoverInfo` | ✓ | 同上，較小的縮圖 |
| `tags` | `TagResponse[]` | ✓ | 見 5.2 |
| `upload_date` | integer | ✓ | Unix 秒 |
| `num_pages` / `num_favorites` | integer | ✓ | |
| `scanlator` | string | | 預設 `""` |
| `pages` | `PageInfo[]` | | `number, path, width, height, thumbnail, thumbnail_width, thumbnail_height`；本 App 不用 |
| `comments` / `comment_count` / `related` / `is_favorited` / `suggestions` | | | 只有 `include` 時出現；不帶時回應中**不存在** |

**和 v1 的差異**：沒有 `images.cover.t`（j/p/w）了；改為 `cover.path` 直接給相對路徑，副檔名在路徑內。

實際值（`tests/fixtures/`）：

| 檔案 | gallery | `cover.path` |
| --- | --- | --- |
| `gallery-api-v2.json` | 228922 | `galleries/1205270/cover.jpg` |
| `gallery-api-v2-webp.json` | 694445 | `galleries/4301004/cover.jpg.webp` ← **雙副檔名** |

> 177013（任務原訂的測試 ID）在 v2 回 `404 Gallery not found`，因此改用 228922；新上傳的書多為 `.webp` 或 `.jpg.webp`，所以另存一份。

### 5.2 `TagResponse`

必要：`id`(int)、`type`(string，例 `language`/`tag`/`artist`/`group`/`parody`/`character`/`category`)、`name`、`slug`、`url`(相對路徑，例 `/language/japanese/`)、`count`(int)。
選填：`description`、`is_community`、`pending_describe_id`、`links`（`TagLink[]`：`service, label, url, handle`）。
→ 現有 `{ type, name }` 的萃取方式不用改。

### 5.3 `GET /api/v2/cdn` → `CdnConfigResponse`

公開、規格未列速率限制。必要欄位 `image_servers: string[]`、`thumb_servers: string[]`。實際回應：

```json
{"image_servers":["https://i1.nhentai.net","https://i2.nhentai.net","https://i3.nhentai.net","https://i4.nhentai.net"],
 "thumb_servers":["https://t1.nhentai.net","https://t2.nhentai.net","https://t3.nhentai.net","https://t4.nhentai.net"]}
```

`GET /api/v2/config`（`ConfigResponse`）是同樣兩個欄位再加 `announcement`，本 App 用 `/cdn` 即可。

### 5.4 封面網址組法（規格 `cdn` 標籤原文要點）

- `path` 是相對路徑；從 `/api/v2/cdn` 取伺服器，**伺服器 + "/" + path** 組成完整網址。
- **不要寫死子網域**，清單會變。
- **path 要原樣使用**，不可猜副檔名、後綴或編號。CDN 會嚴格驗證 URL 格式，**一再請求無效網址會被延長封鎖**。
- 封面屬 thumbnail 類 → 用 `thumb_servers`。實測 `https://t1.nhentai.net/galleries/1205270/cover.jpg` 200 `image/jpeg`；`https://t2.nhentai.net/galleries/4301004/cover.jpg.webp` 200 `image/webp`。（舊的 `t.nhentai.net` 目前也仍 200，但規格說不要寫死。）
- 正常瀏覽速率不會 429；持續高速或打無效網址會暫時封鎖，**429 一律當退避訊號**。
- 整本下載有專用端點 `POST /api/v2/galleries/{id}/download`；本 App 只抓封面，不涉及。

### 5.5 驗證與 User-Agent

- securitySchemes：`Authorization: Key <api_key>`、`Authorization: User <token>`；詳情與 cdn 皆可匿名。本 App 不用。
- 規格要求描述性 UA：`AppName/version (contact or project URL)` → `NH-Shelfie/<版本> (+https://github.com/anson669989/NH-Shelfie)` 符合。

## 8. 實機回報 dev.9：詳情 ✓、封面 ✗（cause=OFFLINE）

- 回報：`url=https://t2.nhentai.net/galleries/1205270/cover.jpg`，cause=OFFLINE。
- 原因判讀：舊版 `downloadCover` 把 `Filesystem.downloadFile` 丟出的非 AppError 錯誤一律交給 `classifyNetworkError`，其預設分支就是 `OFFLINE`，所以 OFFLINE **不代表真的離線**，原始訊息被丟掉。
- 重新確認規格（2026-11-06）：`/api/v2/docs` 只是載入同一份 `openapi.json` 的 Swagger UI，規格內容與第 5 節讀取時完全相同；圖片唯一的說明是 `cdn` 標籤（見 5.4）。封面網址＝`/api/v2/cdn` 的 `thumb_servers` 之一＋`cover.path` 原樣，**格式與副檔名正確**。桌機 curl 同一網址：任何 UA（本 App UA、空 UA、Dalvik、okhttp）皆 `200 image/jpeg 110179 bytes`，伺服器是 nginx（非 Cloudflare）、無 Referer 要求。

### 這次的修改（dev.10）

1. **封面診斷**（`getLastCoverTrace()`，測試連線的 `cover` 段）：`servers`、`userAgent`，以及每次嘗試的 `host`、`url`、`uaSent`、`ms`、`bytes`、`ext`、`error`，與外掛原始錯誤 `message`／`pluginCode`／`data`／`statusInMessage`。`downloadFile` 本身不回傳 HTTP 狀態碼，所以測試連線（`diagnose: true`）在下載失敗後，間隔 3 秒再對同一網址發一次 `CapacitorHttp` HEAD，記在 `probe`（`status`、`contentType`、`contentLength`、`server`，或其原始錯誤）。
2. **換伺服器重試**：失敗就依 `/api/v2/cdn` 的順序換下一台，直到全部（t1→t2→t3→t4）試過，每次間隔 ≥ 3 秒；429 立即停止。每次結果都進 `attempts`。
3. 非 AppError 的下載錯誤不再歸成 `OFFLINE`：只有 `navigator.onLine === false` 才是 OFFLINE，其餘為 `COVER_FAILED`（reason=download），原始訊息保留在診斷。

待實機：按「測試連線」後把診斷整段貼回。重點看 `attempts[].message`／`pluginCode` 與 `probe.status`：probe 若是 200，代表網址與網路沒問題、問題在 `downloadFile`；probe 也失敗則看其錯誤訊息。`uaSent: true` 表示程式有把 `User-Agent` 放進 `downloadFile` 的 headers，外掛是否實際送出要以 probe 對照。
