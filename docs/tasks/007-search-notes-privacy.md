## 階段 A

### 3. 設定：開啟網頁的方式

**目的**：以 Custom Tab（App 內瀏覽器）開網頁後，從網頁「分享」回 App 時，原本的網頁會消失。原因是 MainActivity 是 `singleTask`，被分享喚起時會清掉同一個工作堆疊上方的 Custom Tab。外部瀏覽器跑在自己的工作堆疊，不受影響。

- 設定頁新增「開啟網頁方式」：`外部瀏覽器`（預設）／`App 內瀏覽器`
- 設定鍵：`open_mode`，值 `external` | `custom_tab`，預設 `external`
- 適用所有「開網頁」的地方：收藏頁點封面、新增頁「最近加入」點橫條
- 外部瀏覽器的實作：**不可新增 Capacitor 外掛**（規則 9）。在本地外掛 `nh-webfetch` 加一個 `openExternal(url)` 方法（Java：`Intent.ACTION_VIEW` ＋ `CATEGORY_BROWSABLE` ＋ `FLAG_ACTIVITY_NEW_TASK`，以 try/catch 接 `ActivityNotFoundException`），不用 `resolveActivity`（Android 11 起需要 manifest `queries`）
  - `nh-webfetch` 只准由 `nhSource.js` import（CLAUDE.md），所以由 nhSource 匯出、經 library 給介面呼叫
  - 網址只能是 `fillTemplate` 以整數 ID 組出的 `https://nhentai.net/g/{id}/`（規則 5）；Java 端也要再檢查 https 與網域白名單
- 開不起來時沿用現有備案：複製連結並提示
- 不新增 Android 權限

### 6. ⋮ 單本選單：新增備註欄

- 在封面右上角「⋮」單本選單加一個**單行**備註輸入框（不能換行；貼上的換行字元轉成空白）
- **不限制長度**
- **自動儲存**：離開輸入框（blur）時寫入 `books.note`；內容沒變就不寫；前後空白去掉，空字串存成空值
- 寫入走 library.js（例如 `setNote(galleryId, text)`），參數化 SQL
- 純文字渲染（規則 4），禁用 v-html
- CSV 匯出／匯入已含 note 欄，確認一來一回不會遺失或變形（有測試就補一個含備註的案例）

### 7. 設定：顯示備註

- 設定頁新增「在封面下方顯示備註」開關，設定鍵 `show_note`，預設關閉
- 開啟時，封面牆在現有兩行書名的下方多一行顯示備註，**單行，太長截成「…」**（CSS `text-overflow: ellipsis`）
- 沒有備註的書，這一行留白（維持每格高度一致，虛擬捲動才不會亂跳）
- 開關切換時要重新計算 CoverGrid 的每列高度
- 關閉時畫面與舊版完全相同
- 新增頁「最近加入」也照這個開關顯示備註

### 4. 設定：媽媽模式

**目的**：旁人看到螢幕時不尷尬。

- 設定頁新增「媽媽模式」總開關，設定鍵 `mama_mode`，預設關閉。**只能在設定頁切換**，不做快速切換
- 總開關下方有「詳細設定」，只在總開關開啟時才可操作。詳細設定分成**兩個區塊**，各有區塊標題，視覺上分開：

```
媽媽模式                    [開關]
── 套用頁面 ──────────────────
  收藏頁                    [開關]
  新增頁「最近加入」         [開關]
── 隱藏內容 ──────────────────
  封面                      [開關]
  書名                      [開關]
  備註                      [開關]
```

| 區塊     | 設定鍵               | 說明               | 預設 |
| -------- | -------------------- | ------------------ | ---- |
| 套用頁面 | `mama_scope_library` | 收藏頁封面牆       | 開   |
| 套用頁面 | `mama_scope_add`     | 新增頁「最近加入」 | 開   |
| 隱藏內容 | `mama_hide_cover`    | 封面               | 開   |
| 隱藏內容 | `mama_hide_title`    | 書名               | 關   |
| 隱藏內容 | `mama_hide_note`     | 備註               | 關   |

- 隱藏封面：顯示**固定淺灰色**的純色方塊（不跟主題色，深色模式也是淺灰），沒有圖示也沒有文字。**完全不載入本機圖片**（不放 `<img>`），快速捲動時才不會閃出真實封面
- 書的狀態佔位圖（載入中／找不到這本／資料讀取失敗／封面失敗）照舊顯示，因為那不是書的內容
- 隱藏書名／備註：該行留白，維持格子高度；左下角 ID 照常顯示
- ⋮ 單本選單是使用者主動點開的，**照常顯示**完整標題與備註
- （追加）「詳細設定」預設收合，點「詳細設定」才展開兩個區塊，減少佔用畫面
- （追加）媽媽模式套用到新增頁時，「最近加入」每本書的資料夾標示自動隱藏（`viewOptions` 的 `hideFolders`）

### 2. 新增頁「最近加入」

- **點整條橫條**（不只是圖片）就開網頁，依 `open_mode`
- 書名下方顯示這本書目前所在的資料夾（多個資料夾用「、」分隔；沒有就顯示「未分類」）
- **長按橫條**會開出和收藏頁一樣的「⋮ 單本選單」。要把現有選單抽成共用元件，或讓兩邊呼叫同一個 DialogHost 入口，不要複製一份
- 在任何地方（⋮ 選單、多選批次分類、收藏頁）改了資料夾，最近加入的資料夾標示都要**立即更新**。用現有的資料變更通知機制，沒有的話就在 library.js 加一個「書籍變更」事件，兩頁都訂閱
- 設定頁新增「最近加入顯示筆數」，五個選項：10／20／30／40／50，預設 20。設定鍵 `recent_limit`
- 長按不可觸發文字選取（`user-select: none`），返回鍵先關選單（規則 13）

## 階段 B

### 5. 資料夾拖曳排序

- 位置：收藏頁「資料夾篩選」下拉清單（階段 C 之前就是現有的資料夾下拉選單）
- 每列自建資料夾左邊顯示拖曳把手（≡）。**只有按住把手才能拖曳**，按下後短暫延遲（約 150 ms）才開始，避免和捲動衝突
- 「全部」「未分類」固定在最上方，沒有把手，也不能被拖到它們上面
- 拖到清單上緣或下緣、但還沒到目標位置時，**自動往上／往下捲動**，越靠近邊緣捲得越快
- 拖曳時被拖的那一列浮起並跟手，其他列即時讓位；放開才寫入
- 放開時在**一個交易**內更新所有資料夾的 `sort_order`；失敗就回滾，並把畫面還原成原本的順序
- 移除舊的「長按上移／下移一格」
- 拖曳用 Pointer Events 自己寫（約 100–150 行），不新增 Capacitor 外掛，也不另外引入套件。若認為一定要引入純 JS 拖曳套件，先在回報裡說明理由，讓使用者決定
- 現有的改名／刪除入口保留不動

## 階段 C

### 1. 收藏頁：搜尋與篩選

#### 版面

```
原本： [資料夾選擇 ▼]                       [排序 ▼]
新版： [標籤／作者／社團 搜尋（可打字）]     [排序 ▼]
       [作品名稱／備註／ID 搜尋]            [資料夾篩選 ▼]
```

兩列都要能在小螢幕排得下；safe-area 規則照舊（規則 11）。

#### 第一列：標籤／作者／社團搜尋

- 點下去後輸入框**仍可打字**，下方展開選項清單
- 每列選項從左到右是：☐ 勾選框｜類型標籤｜名稱｜本數
  - 類型只列三種：`tag`（標籤）、`artist`（作者）、`group`（社團）。類型標籤文字要四語化
- 打字即時篩選（不分大小寫，比對名稱的任一部分）
- 已勾選的選項排在最上面，其他依本數由多到少
- 選項可能有上千個：清單要做虛擬捲動，或只渲染前 200 筆並提示「繼續輸入以縮小範圍」
- 收合時輸入框顯示「已選 N 個」，旁邊有清除鈕
- **多選邏輯：「且」**（書要同時有所有勾選的標籤／作者／社團才顯示）

#### 第二列：文字搜尋

- 比對**作品名稱（英／日標題）、備註、ID**，三者任一符合就顯示
- 不分大小寫；輸入停止約 300 ms 後才查詢
- SQL 用參數化的 `LIKE ? ESCAPE '\'`，使用者輸入的 `%`、`_`、`\` 要跳脫（規則 3）
- 列表查詢**不可 SELECT book_raw**（規則 3）。英／日標題要搜得到，所以要確認 books 有這兩欄，沒有的話在 v3 一併補欄位，由 book_raw 回填

#### 第二列：資料夾篩選

- 取代原本的資料夾下拉選單，改成**多選**
- 清單：「全部」「未分類」固定最上方，下面是自建資料夾（含本數、拖曳把手，見第 5 點）
- 「全部」等於不篩選：勾「全部」會清掉其他勾選；勾任何其他項會取消「全部」；全都不勾就自動回到「全部」
- **多選邏輯：「或」**（書在任一個勾選的資料夾裡就顯示；「未分類」也可以和其他資料夾一起勾）

#### （追加）快速清除與標題顯示

- 資料夾篩選與標籤篩選的下拉清單，**右上角都有「全部清除」**：資料夾回到「全部」、標籤取消所有勾選（打的字保留）
- 修正：資料夾清單最上方的標題（原「選擇資料夾」，現為「資料夾篩選」）在清單很長時被擠扁、只顯示一半。標題列改成固定高度，捲動時固定在頂端

#### 三個條件的組合

`標籤條件（且）` **且** `資料夾條件（或）` **且** `文字條件`

- 有任何篩選時，封面牆上方顯示「找到 N 本」與「清除全部篩選」
- 多選模式的「全選」只選目前篩選結果
- 排序：只選一個資料夾（或「全部」／「未分類」）時，沿用該資料夾記住的排序；選多個資料夾時，用「全部」的排序
- 篩選條件要不要在重開 App 後保留：只保留資料夾篩選（記在 settings），文字與標籤每次開 App 清空

#### 資料：schema v3

- 在 `MIGRATIONS` **尾端**新增 v3（規則 7），遷移前自動備份照舊：
  - `tags(id INTEGER PK, type TEXT, name TEXT, UNIQUE(type, name))`
  - `book_tags(gallery_id INTEGER, tag_id INTEGER, PRIMARY KEY(gallery_id, tag_id))`，加 `book_tags(tag_id)` 索引
  - 存全部 7 種類型（以後要擴充不必再遷移），介面只顯示 tag／artist／group
- **標籤解析**放在 `parse.js`（純函式）：同時支援 `api-v1` 與 v2 的 `raw_format`，欄位缺少不崩潰；用存下的真實回應寫單元測試
- **舊資料回填**：遷移本身只建表。啟動後由 library.js 在前景分批（例如每批 100 本）從 `book_raw` 本地解析寫入，**不上網**；完成後記 `tags_backfilled` 設定鍵，下次不再做
- **新書**：meta 工作者寫 `books` 書名與 `book_raw` 的那個交易裡，一併寫 `tags`／`book_tags`（規則 2）
- 刪除書時一併刪 `book_tags`；沒有任何書使用的 tag 可以留著，選項清單只列本數 > 0 的
- 還在 `meta_pending` 的書沒有標籤，是正常現象
